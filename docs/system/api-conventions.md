# API conventions

The API is the product's public surface. The enterprise's own applications use it, and our review UI is only a client of it: there are no private endpoints for our own frontend.

Each Cell has its own host and its own JWKS. There is no shared hostname in a client's integration.

## Authentication

- `Authorization: Bearer <jwt>`, verified against the Tenant's JWKS, issuer and audience. Fail closed.
- The Tenant is read from the token. **A request body that carries a Tenant id is rejected with `400`, never trusted.**
- Connectors use workload identity: client credentials or mTLS, short-lived, per Tenant. A person's token is never used as a service credential.

## Paths and versioning

- Base path `/v1`. Additive changes only within a version. A breaking change is a new major path.
- `openapi.json` is generated by `utoipa`, committed as a release artifact, and consumed by the frontend repository. CI fails if the generated file differs from the committed one.

## Shapes

- Money is `{ "amount_minor": 5000000, "currency": "KES" }`. Never a float.
- Timestamps are RFC 3339, UTC.
- Identifiers are opaque strings. Clients do not parse them.
- Enums may gain values. Clients must tolerate an unknown value rather than crash.

## Long work

A Case run may take minutes:

```http
POST /v1/cases/{case_id}/runs
Idempotency-Key: 7b1c...
→ 202 Accepted
   Location: /v1/runs/{run_id}
```

Clients poll `GET /v1/runs/{run_id}`, which returns `queued | running | drafted | stopped | escalated`. A `stopped` run returns its Discrepancies with both values and both Anchors, so the UI can render them side by side without a second call.

## Errors

`application/problem+json` (RFC 9457) with a stable `code`, a human `detail`, and a `trace_id`. Never a bare 500, never an error message that leaks another Tenant's data. `409` for a state conflict, `422` for a Pack validation failure with the failing path.

## Idempotency

Every `POST` that creates or changes state requires `Idempotency-Key`. A replay returns the original response. The key is scoped to the Tenant.

## Pagination

Cursor-based: `?limit=&cursor=`. No offsets. Stable order by `(created_at, id)`.

## Observability

Every response carries `x-request-id`; every log line carries `trace_id`, `tenant_id` and `case_id` where they exist. Audit of human actions is Evidence, not logs — logs are for operators and may be dropped.

## What a client must be able to do on day one

1. Push a document, or list what a Connector collected.
2. Open a Case from a Trigger.
3. Run the Case and receive `drafted`, `stopped` or `escalated`.
4. Read a draft with every number linked to an Anchor.
5. Resolve a Discrepancy and sign the Decision.
6. Export the regulator bundle.

If a screen in our own UI needs something not on this list, the API is wrong, not the UI.
