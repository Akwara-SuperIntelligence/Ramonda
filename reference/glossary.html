The loop

Agent
An LLM that autonomously chooses tools in a loop until a task is done, rather than following a code path a developer fixed in advance. Avoid: bot (that is the product surface), workflow
Harness
The code around the model that assembles context, exposes tools, executes tool calls, and decides when to stop. Avoid: framework, runtime
Agent loop
The repeating three-step cycle: the model picks a tool, the harness executes it, the result is appended to context, repeat. Avoid: agentic loop, ReAct loop
Turn
One user-visible exchange, from an incoming message or trigger to the agent's next reply or deliberate silence. Avoid: step, iteration
Tool call
A structured request from the model naming a tool and its arguments, which the harness — not the model — executes. Avoid: function call (except as an API field), action

State and survival

Execution state
Where a run currently is: the messages so far, the pending tool call, the step counter. Avoid: context (only the part sent to the model), memory
Durable execution
A run model where progress is journaled, so a retry after a crash resumes at the last completed step instead of replaying from the start. Avoid: checkpointing (weaker, related), retries
Always-on agent
An agent whose process, state, and wake-up path live outside your terminal, so it can act while you are gone and resume after a restart. Avoid: autonomous agent, background agent
Use it or lose it

If you cannot use a term in a sentence about your own build, it has not landed yet. The quiz in lesson 01 is a retrieval check, not a reading check.
